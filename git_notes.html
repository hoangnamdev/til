STEP 01

Installing Git

Package installation commands tailored to your target platform.

# Refresh system repos and install latest git build
sudo pacman -Syu git
# Standard apt repository install
sudo apt update && sudo apt install -y git
# Windows Package Manager (PowerShell or Terminal)
winget install --id Git.Git -e --source winget
Verify installed version: git --version
STEP 02

Identity & Global Configuration

Written directly to ~/.gitconfig. Required before creating commits.

# Commit identity metadata attached to every snapshot
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
# Set industry standard default branch name (avoids legacy 'master')
git config --global init.defaultBranch main
# Avoid accidental messy merge bubbles when pulling
git config --global pull.rebase true
# Editor for commit messages (nano, vim, or "code --wait")
git config --global core.editor "nano"
Inspect current config: git config --list --show-origin
STEP 03

Remote Server Authentication (GitHub / GitLab)

Password authentication was deprecated. Choose GitHub CLI (modern wizard) or traditional Ed25519 SSH keys.

# Automates browser verification, SSH key generation, and token registration in one terminal wizard
gh auth login
Prompt selections: GitHub.com → SSH → Paste one-time code in browser.
# 1. Generate modern Ed25519 elliptic curve keypair
ssh-keygen -t ed25519 -C "you@example.com"
# 2. Launch background SSH agent & load private key
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
# 3. Print public key (paste output into GitHub Settings → SSH Keys)
cat ~/.ssh/id_ed25519.pub
Test connection: ssh -T git@github.com
STEP 04

Starting Repositories & Ignoring Secrets

Initialize brand new directories, clone remotes, and prevent accidental secret check-ins.

Start From Scratch Locally
# Initialize directory with 'main' branch
git init -b main
Creates internal hidden .git/ directory tracking engine.
Clone Remote Repository
# Clones full history into folder 'repo'
git clone git@github.com:user/repo.git
Configures pointer origin pointing back to source.
Untrack Files Without Deleting From Disk
# 1. Append ignored patterns to .gitignore
echo ".env" >> .gitignore
# 2. Pull already-tracked file out of Git index (keeps local copy intact)
git rm --cached .env
git rm -r --cached node_modules/
# 3. Commit untracked state to repo
git commit -m "chore: stop tracking sensitive files"
STEP 05

Daily Core Loop (Stage → Diff → Commit → Amend)

The primary cycle used 95% of the time during active coding.

# 1. Compact status check (M = Modified, ? = Untracked, A = Added)
git status -s
# 2. Stage specific file, or stage ALL modifications in repository
git add file.js
git add .
# 3. View working unstaged diffs vs. staged changes ready to be committed
git diff
git diff --staged
# 4. Record permanent snapshot with clear imperative message
git commit -m "feat: concise description of work done"
# Quick fix: Fold newly staged changes into previous commit without prompt
git commit --amend --no-edit
To combine staging tracked files and committing into one step: git commit -am "message"
STEP 06

Branching & Switching Context

Keep experiments separate from production code using lightweight pointer branches.

# Create and switch to new branch immediately (-c = create)
git switch -c feature/login
# Switch between existing branches
git switch main
# Jump back to previous branch (like cd -)
git switch -
# Safely delete merged branch (-D for force delete)
git branch -d feature/login
# Legacy: create (-b) and switch
git checkout -b feature/login
# Legacy: switch to existing branch
git checkout main
STEP 07

Forks, Remotes & Upstream Synchronization

When working with open-source forks: origin = your fork, upstream = original repository.

# 1. View configured remotes & wire up original repo as 'upstream'
git remote -v
git remote add upstream https://github.com/original-owner/repo.git
# 2. Download latest upstream commits without modifying working tree
git fetch upstream
# 3. Bring local main up-to-date with upstream parent repo
git switch main
git merge upstream/main
# 4. Push branch to your personal fork (-u links tracking branch)
git push -u origin feature/login
Always pull with rebase to keep history clean: git pull --rebase origin main
STEP 08

Merging vs. Rebasing

Merging joins branches with a commit; rebasing replays commits sequentially for a linear history.

Standard Merge
# Switch to target receiver branch
git switch main
# Creates merge commit with two parents
git merge feature/login
Safe on shared public branches. Preserves full chronological context.
Rebase (Clean Linear Tree)
# Replays feature commits on top of current main
git switch feature/login
git rebase main
# Squash and tidy last 3 commits interactively
git rebase -i HEAD~3
In interactive editor: replace pick with squash to merge micro-commits.
STEP 09

Resolving Conflicts & Emergency Exits

When branches touch the exact same line, Git pauses and writes conflict markers for you to resolve.

# Conflict markers injected into files:
<<<<<<< HEAD (current branch version)
const API_URL = "https://api.internal.dev";
=======
const API_URL = "https://api.production.com";
>>>>>>> feature/login (incoming version)
# 1. Edit file manually, delete marker lines, and stage resolved file
git add resolved_file.js
# 2. Resume operation depending on what you initiated
git rebase --continue
# Or if resolving inside a merge:
git merge --continue
# 3. Emergency escape hatch (cancels everything safely)
git rebase --abort
git merge --abort
Run git status to see every file flagged under "Both modified".
STEP 10

Undoing Mistakes, History & Reflog Rescue

Nothing is truly lost in Git until cleaned by garbage collection. Rescue commits using reflog.

# Visual concise tree of all branches
git log --oneline --graph --all
# Discard unstaged changes in working file
git restore file.js
# Unstage file back to working tree without modifying its content
git restore --staged file.js
# Safe undo on public shared branch: commits the exact opposite diff
git revert 7b3a19c
# Soft undo: resets last commit, but retains all file edits in staging
git reset --soft HEAD~1
# Destructive undo: nukes commit and all uncommitted code
git reset --hard HEAD~1
# Emergency rescue: view chronological history of EVERY action & restore
git reflog
git reset --hard HEAD@{1}
STEP 11

Precision Tools: Cherry-Picking & Release Tags

Port single commits across branches and create production release tags.

Cherry-Pick Commits
# Apply one specific commit onto current branch
git switch main
git cherry-pick 3fa82c1
# Bail out if conflicts appear:
git cherry-pick --abort
Ideal for pulling a bugfix from an unmerged branch into production.
Semantic Release Tags
# Create annotated release tag
git tag -a v1.0.0 -m "Release version 1.0.0"
# Tags are NOT pushed by default; push explicitly:
git push origin v1.0.0
git push origin --tags
GitHub automatically converts pushed tags into Release downloads.
STEP 12

Temporary Stashing

Shelve dirty uncommitted work without committing, switch tasks, then pop it back.

# Save current dirty workspace (including untracked files with -u)
git stash -u -m "wip: temporary work"
# View saved stashes shelf
git stash list
# Reapply latest stash and pop it from shelf
git stash pop
# Discard latest stash without applying
git stash drop
STEP 13

Power Tools: Worktrees & Submodules

Work on multiple branches simultaneously in sibling directories without switching branches.

Git Worktrees (Parallel Folders)
# Check out branch into sibling folder
git worktree add ../hotfix hotfix-branch
# Inspect active worktrees
git worktree list
# Cleanup when finished
git worktree remove ../hotfix
No need to stash or wait for builds when fixing an urgent bug!
Git Submodules (Nested Repos)
# Clone repo including all nested repos
git clone --recurse-submodules repo.git
# Initialize missing submodules in existing repo:
git submodule update --init --recursive
Ensures nested dependencies are cloned and checked out properly.
